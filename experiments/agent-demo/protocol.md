# Agent experiment protocol (preliminary, read-only)

Purpose: observe whether an unmodified coding agent picks the deployment-correct implementation path when given
CASE's validity-labeled package versus baseline context (paper Section IV, RQ2/RQ3). Nothing is deployed.

## Fixed across runs
- One frozen model/agent and version (record it in `results-template.csv`), one task prompt, one token budget B
  (default 1500 approx. tokens, same for every condition), same candidate pool (generated by the harness).
- Fresh session per run; no repository access beyond the prompt unless you deliberately test that variant.
- Only evidence available at the snapshot time `t` is in the prompt.

## Conditions
`SEMANTIC_ONLY`, `RECENCY_FILTERED`, `SEMANTIC_PLUS_RAW_CONFIG`, `CASE_VALIDITY_PACKAGE`, plus ablations
`CASE_NO_FLAG_EVIDENCE` and `CASE_NO_LINEAGE_EVIDENCE`.

## Steps
1. Generate prompts: `scripts/make-prompts.sh "Extend the merchant trust score with a new return rate signal" eu-prod`
   (repeat for `us-prod`, `apac-prod`). `prompts/<deployment>/run-order.txt` is a randomized order.
2. Run each prompt in a fresh session in that order; save the agent's plan/patch under `runs/<deployment>/<run_id>/`.
3. Two evaluators, blind to the condition, label each plan using the rubric below, independently.
4. Log one row per run in `results-template.csv` (copy it to `results.csv`).
5. Compare against the reference solutions: `us-prod-graphql.patch` (GraphQL: new `TrustSignalProvider` bean) and
   `eu-prod-rest.patch` (legacy REST: extend the formula). `apac-prod` has no single correct patch; the correct plan
   uses REST and flags the GraphQL cohort question. Validate the references with `scripts/check-reference-solutions.sh`.

## Rubric (per plan)
- architecture_choice: REST | GraphQL | both | asks-for-verification.
- operational_compatibility_violation (primary outcome): yes if the plan implements on a path that is not live for
  the target deployment at `t`.
- affected_services_correct, flag_deployment_compatible: yes/no. justification_score_1to5. tests_recommended: yes/no.

## Analysis
Unit of analysis is the task-deployment pair. Report paired risk differences with task-bootstrap confidence
intervals and discordant counts; report evaluator agreement separately. With 3 deployments this is a smoke test, not
an effectiveness claim.
